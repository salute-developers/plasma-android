## ADDED Requirements

### Requirement: Публичное value-состояние Error
Compose `CheckBox` SHALL поддерживать четвёртое value-состояние **Error**, равноправное и взаимоисключающее с существующими On/Off/Indeterminate. Состояние SHALL задаваться через новый публичный enum и новые composable-перегрузки `CheckBox(...)`, отдельные от существующих перегрузок на `androidx.compose.ui.state.ToggleableState`.

#### Scenario: Отображение состояния Error
- **WHEN** вызывающий код передаёт новой перегрузке `CheckBox(...)` значение состояния Error
- **THEN** компонент отображает глиф-крестик вместо галочки или палочки

#### Scenario: Существующие вызовы не ломаются
- **WHEN** существующий код продолжает вызывать `CheckBox(state: ToggleableState, ...)` (без изменений в вызывающем коде)
- **THEN** компонент компилируется и ведёт себя как раньше, без доступа к состоянию Error и без каких-либо изменений поведения On/Off/Indeterminate

### Requirement: Error задаётся только программно
Компонент SHALL НЕ переводить себя в состояние Error самостоятельно в результате клика или другого пользовательского взаимодействия. Error SHALL быть достижимо только через явную передачу этого значения вызывающим кодом (`state`/`value` параметр).

#### Scenario: Клик по компоненту не производит Error
- **WHEN** компонент находится в состоянии On, Off или Indeterminate и пользователь кликает по нему
- **THEN** `onClick`/`onCheckedChange` вызывается с тем же контрактом, что и раньше; сам компонент не переключает себя в Error

### Requirement: Анимированная отрисовка глифа Error
Глиф Error (крестик) SHALL отрисовываться тем же внутренним parametric-path механизмом, что и глиф Checked/Indeterminate (не через внешне переданные Composable-иконки), и SHALL поддерживать анимацию появления/исчезания.

#### Scenario: Reveal-анимация при появлении Error
- **WHEN** состояние компонента переключается из Off в Error
- **THEN** крестик проявляется анимированно (progressive reveal), аналогично текущей анимации появления галочки/палочки из Off

#### Scenario: Кроссфейд при прямом переходе между семьями глифов
- **WHEN** состояние компонента переключается напрямую (минуя Off) между Error и Checked, или между Error и Indeterminate
- **THEN** переход отображается кроссфейдом (исчезание старого глифа при одновременном появлении нового), а не морфингом общего пути

### Requirement: Стилевой контракт для Error
Стилевой слой `CheckBox` (`CheckBoxStates`, `CheckBoxColorValues`) SHALL поддерживать состояние Error как дополнительное значение `ValueState`, настраиваемое через существующий механизм `StatefulValue<Brush>`, без изменения поведения для существующих значений Checked/Indeterminate.

#### Scenario: Кастомизация цвета Error через стиль
- **WHEN** стиль компонента задаёт цвет для набора состояний, включающего `CheckBoxStates.Error`
- **THEN** компонент в состоянии Error отображается с этим цветом, а поведение для Checked/Indeterminate/Off остаётся прежним
