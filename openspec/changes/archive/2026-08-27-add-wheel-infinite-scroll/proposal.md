## Why

Compose-колесо (`sdds-core/uikit-compose`, `BaseWheel.kt`) сейчас всегда имеет жёсткие границы прокрутки: списки вроде часов, минут или дней недели не зацикливаются — докрутив до последнего элемента, пользователь упирается в край, хотя семантически такие значения цикличны. Наивное добавление зацикливания через классический приём "размножить список и брать `index % size`" несовместимо с текущей реализацией: `WheelTextMetrics.widestItem` в `BaseWheel.kt` для расчёта ширины колеса проходит по **всему** списку айтемов с intrinsic-text-измерением каждой строки — если этот список окажется размноженным (или бесконечным), измерение станет неприемлемо дорогим или вовсе не завершится. Нужен способ включить зацикленную прокрутку для отдельных колёс, не затрагивая стоимость расчёта ширины.

## What Changes

- В `WheelDataSet` добавляется новое поле `looping: Boolean = false` — зацикливание прокрутки становится свойством конкретного колеса (а не всего компонента `Wheel`), что позволяет, например, зациклить часы и минуты, оставив год или AM/PM неизменными.
- `BaseWheel` при `looping = true`:
  - переключает `LazyColumn` на зацикленную виртуальную индексацию (`Int.MAX_VALUE` позиций, реальный айтем — `virtualIndex.mod(items.size)`) вместо конечного списка с жёсткими границами;
  - продолжает измерять ширину (`WheelTextMetrics`) только по реальному, немодифицированному `items: List<WheelItemData>` — виртуальное индексное пространство прокрутки никогда не участвует в измерении;
  - отключает dummy-паддинг краёв (`rememberExtendedList`/`DataEdgePlacement.WheelCenter`) — у зацикленного колеса нет краёв, поэтому `dataEdgePlacement` для такого колеса не применяется;
  - выбор текущего элемента (`onItemSelected`) и управление стрелками (`hasControls`) корректно работают в зацикленном режиме без клампа по границам `[0, items.size - 1]`.
- Явное архитектурное расхождение с существующей View-реализацией (`sdds-core/uikit`, `Wheel`/`WheelListView`, свойство `infiniteScrollEnabled`): там зацикливание — глобальная настройка на весь компонент и применяется ко всем колонкам сразу, а сам механизм основан на конечном множителе (`× 20`) с телепортом при остановке скролла. В Compose-версии зацикливание умышленно per-колёсное и не требует recenter/teleport-логики — эти решения не переносятся из View-реализации.
- Возможный крайний случай (`items.size < visibleItemsCount`) не ограничивается явной проверкой — при зацикливании допустимо, что один и тот же айтем одновременно виден в нескольких местах вьюпорта.

## Capabilities

### New Capabilities
- `wheel-compose-looping`: зацикленная (бесконечная) прокрутка отдельного колеса в Compose-компоненте `Wheel` — API (`WheelDataSet.looping`), развязка измерения ширины от индексного пространства прокрутки, поведение выбора элемента и управления при зацикливании.

### Modified Capabilities
(нет — существующие спеки `wheel-compose-selection-indicator` и `wheel-text-after-mode` описывают другое поведение колеса и не меняются этим изменением)

## Impact

- Модуль: `sdds-core` → `uikit-compose` (Kotlin Multiplatform `commonMain`).
- Затронутые файлы:
  - `sdds-core/uikit-compose/src/commonMain/kotlin/com/sdds/compose/uikit/Wheel.kt` — публичный API `WheelDataSet` получает новое поле `looping`.
  - `sdds-core/uikit-compose/src/commonMain/kotlin/com/sdds/compose/uikit/internal/wheel/BaseWheel.kt` — логика измерения ширины (`WheelTextMetrics`), формирования списка (`rememberExtendedList`), `LazyColumn`/`LazyListState`, обработка выбора элемента и управляющих стрелок.
- Публичный API: изменение аддитивное — новое поле `WheelDataSet.looping` со значением по умолчанию `false`, обратная совместимость сохраняется (существующие вызовы конструктора и `copy()` не ломаются).
- Токены/докогенерация/Gradle-конвенции: не затрагиваются.
- Проверка: `:sdds-core:uikit-compose:test`, `:sdds-core:uikit-compose:detekt`, `:sdds-core:uikit-compose:spotlessApply`; при необходимости — полный `./gradlew testAll`.
