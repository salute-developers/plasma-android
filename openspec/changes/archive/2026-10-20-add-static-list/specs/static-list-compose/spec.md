## ADDED Requirements

### Requirement: Статический режим списка StaticList
Компонент `StaticList` в `sdds-core/uikit-compose` SHALL быть нескроллируемым контейнером, принимающим контент-контракт `LazyListScope.() -> Unit` (`item`/`items`/`itemsIndexed`) и раскладывающим элементы вертикально по высоте содержимого (не на базе `LazyColumn`). `StaticList` SHALL быть безопасен для вложения во внешние прокручиваемые контейнеры, включая компонент `List`.

#### Scenario: Секция внутри прокручиваемого List
- **WHEN** `StaticList` с несколькими `ListItem` размещён внутри `item {}` прокручиваемого `List` (или иного вертикально скроллируемого контейнера)
- **THEN** содержимое измеряется и отображается по своей содержимой высоте, без исключения измерения (`IllegalStateException`) и без собственной прокрутки; прокручивается только внешний контейнер

#### Scenario: Отсутствие прокруточных параметров в API
- **WHEN** разработчик смотрит сигнатуры `StaticList(...)`
- **THEN** в них отсутствуют параметры `state: LazyListState`, `flingBehavior`, `userScrollEnabled`; присутствует `reverseLayout`, инвертирующий порядок элементов

#### Scenario: Eager-композиция элементов
- **WHEN** в `StaticList` объявлено N элементов (`item`/`items(count = N)`)
- **THEN** все N элементов скомпонованы независимо от видимой области (ленивая композиция отсутствует по определению режима)

### Requirement: Визуальный контракт с существующим List через ListStyle
`StaticList` SHALL принимать стиль типа `ListStyle` со значением по умолчанию `LocalListStyle.current` и SHALL разрешать из него фон (`colors.backgroundBrush`), форму (`shapes`), вертикальный зазор и внутренние отступы (`dimensions`) так же, как `List`. Новый стилевой тип SHALL НЕ вводиться; существующие сгенерированные бренд-стили `ListStyle` SHALL применяться к `StaticList` без изменений.

#### Scenario: Бренд-стиль List применим без изменений
- **WHEN** вызывающий код передаёт `StaticList(style = <существующий бренд-стиль ListStyle>)` (например, `List.S.HasBackground.style()`)
- **THEN** контейнер отображается с фоном, формой и отступами этого стиля, идентично отображению того же стиля у `List`

#### Scenario: Зазор из стиля
- **WHEN** стиль задаёт `dimensions.gap`
- **THEN** между соседними элементами статического списка применяется указанный вертикальный зазор; при незаданном (`Unspecified`) зазоре элементы располагаются вплотную

### Requirement: Propagation стилей элементов и разделителей
`StaticList` SHALL предоставлять дочернему контенту `LocalListItemStyle` из `style.listItemStyle` и `LocalDividerStyle` из `style.dividerStyle` — по образцу `List` — чтобы `ListItem` и `Divider` внутри контента использовали вложенные стили стиля списка без явной передачи параметров стиля.

#### Scenario: ListItem и Divider наследуют стиль секции
- **WHEN** внутри `item {}` вызываются `ListItem(...)` и `Divider()` без явного параметра `style`
- **THEN** они отображаются с `listItemStyle`/`dividerStyle` из стиля, переданного в `StaticList`

### Requirement: Семантика контент-контракта LazyListScope в статическом режиме
Записи, объявленные через `LazyListScope`, SHALL рендериться в порядке объявления с передачей индекса в content-лямбду. Необязательный `key` элемента SHALL применяться как стабильная идентичность композиции. `contentType` SHALL игнорироваться (отсутствие переиспользования элементов), и это расхождение SHALL быть задокументировано в KDoc.

#### Scenario: Элементы с ключами
- **WHEN** элементы объявлены с `key` (`item(key = ...)`, `items(count, key = ...)`)
- **THEN** элементы отображаются в том же порядке, а их идентичность в композиции стабильна при изменении данных с теми же ключами

#### Scenario: Контент без ключей и contentType
- **WHEN** элементы объявлены без `key`, с или без `contentType`
- **THEN** элементы отображаются в порядке объявления; наличие/отсутствие `contentType` не влияет на отображение

### Requirement: Motion-поведение, совместимое с List
`StaticList` SHALL поддерживать motion-стиль `ListMotionStyle` (переиспользование существующего, без ввода нового типа): публичная перегрузка, принимающая `Motion<ListMotionStyle>`, и перегрузка с `interactionSource`, из которой motion строится через `rememberListMotion` — по образцу перегрузок `List`.

#### Scenario: Анимация цвета фона
- **WHEN** motion-стиль задаёт целевое значение цвета фона для текущего контекста взаимодействия
- **THEN** фон статического списка перекрашивается анимированно, тем же механизмом, что и у `List`

### Requirement: Аддитивность публичного API
Изменение SHALL быть аддитивным: публичные API `List`, `ListStyle`, `ListItem`, `ListMotionStyle` и их поведение НЕ изменяются; дамп публичного API `sdds-core/uikit-compose` пополняется только новыми символами `StaticList*`. Сгенерированные файлы `tokens/**` и конфигурация внешней кодогенерации не изменяются.

#### Scenario: Существующие вызовы List не ломаются
- **WHEN** существующий код продолжает вызывать `List(...)`/`ListItem(...)` без изменений
- **THEN** код компилируется и ведёт себя точно как до появления `StaticList`, а `apiCheck` проходит после обновления дампа новыми символами

#### Scenario: Бренд-токены не требуют перегенерации
- **WHEN** сборка бренд-модуля `tokens/*` выполняется без каких-либо изменений в `theme-converter`/themebuilder-конфигурации
- **THEN** `StaticList` доступен и стилизуется уже сгенерированными стилями `ListStyle`
