## Context

Плагин превью — wasm-приложение (Kotlin/Wasm, Compose Multiplatform 1.8.2, Skiko 0.9.4.2), которое рисует настоящие
Compose-компоненты по payload протокола Preview Protocol. Иконка компонента — `ImageSource`, которому нужен `Painter`.
Протокол уже содержит `PreviewAssetType.SVG` и ресурсы `assets[]` (шрифты загружаются так же), но плагин отвечал
`unsupported_asset` для ссылок на изображения.

## Decisions

**Иконка — ресурс payload, а не часть плагина.** Клиент DSB по значению свойства находит иконку в каталоге и кладёт в
`assets` ресурс `{id: "icon:<значение>", type: SVG, url}`. Значение свойства не меняется (`literal`), поэтому остальной
код стилей (`iconValue`, предупреждения `unknown_icon`) работает как раньше: `PreviewIconRegistry` теперь собирается из
загруженных ресурсов. Альтернатива — свойство `assetRef` — отвергнута: она потребовала бы менять разбор значений во всех
сгенерированных фабриках стилей и протокол валидации.

**Рисует Skia SVG, собственного разбора SVG нет.** `skiko.wasm` (8,4 МБ, поставляется плагином в любом случае) уже содержит
нативные функции `SVGDOM__1nMakeFromData` и `SVGDOM__1nRender`; обёртка `org.jetbrains.skia.svg.SVGDOM` приходит
транзитивно через `compose.ui`. `SkiaSvgIconFactory` разбирает SVG один раз, а `Painter` растеризует его в `ImageBitmap`
под размер отрисовки и рисует с `alpha` и `colorFilter`, как `SvgPainter` Compose Resources, но без зависимости
`components-resources`. Рост плагина — около 6 КБ.

Проверено на SVG каталога: пути с `fill-rule`, группа с `clip-path` и `rect` на весь viewport (144 из 6486 файлов),
`circle`, `stroke` и `opacity` на группе рисуются корректно; `<metadata>` с JSON внутри не мешает.

**Альтернативы.**
- Ручной разбор `d` в `ImageVector.addPathNodes`: вектор, но свой парсер и обработка `circle`, `stroke`, `opacity`.
- Браузерный разбор (`Image` → `ImageBitmap`): растр, зависит от DPR, асинхронный интероп внутри композиции.
- Генерация списка иконок из каталога в CI: реестр остаётся вшитым, а Android-набор не содержит часть иконок каталога.
- Все иконки `SddsIcons`: плагин 23,2 МБ.

**Ошибки загрузки не останавливают render.** Любое исключение при скачивании или разборе одного SVG пропускает эту
иконку; она получает `unknown_icon`, остальной payload рисуется.

## Risks / Trade-offs

- Скачивание на каждый render: ответы кешируются `CachingPreviewAssetResolver` по адресу (или digest), поэтому повторные
  render с теми же иконками сети не требуют.
- Растр вместо вектора: при смене размера битмап пересоздаётся; для иконок 16–36 px это незаметно.
- Превью показывает web-рисунок иконки (как в билдере), а Android-приложение — рисунок `SddsIcons`; у ~1% иконок они
  различаются (выборка из 900 пар: 9 расхождений). Это расхождение наборов, а не плагина.
- Плагин зависит от доступности SVG каталога и CORS бакета; без них иконки рисуются по умолчанию с `unknown_icon`.
